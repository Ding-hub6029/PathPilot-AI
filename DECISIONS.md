# DECISIONS.md — PathPilot AI Day 1

| # | Decision | Rationale |
|---|---|---|
| 1 | Day 1 backend only; no frontend, no GitHub push (original scope) | Task scope: another agent owns `frontend/`; no push requested for Day 1. (Superseded 2026-11-24: frontend integrated and Day 1 pushed — see #18.) |
| 2 | Two independent tracks (undergraduate / taught_masters), cross-track profiles rejected with 422 `TRACK_MISMATCH` | Competition product design; prevents meaningless cross-track matches. |
| 3 | Only 2 real programmes in v1, each fact traced to a source id + excerpt | No fabricated data; Day-1 scope is a working rules engine, not coverage. |
| 4 | Rules/template explain mode with no AI key; `ai_status=unavailable` | No cloud AI key available and none required by the competition; the explain endpoint must work without one. |
| 5 | ProviderAdapter reads only env vars (`AI_PROVIDER`, `AI_MODEL`, `AI_API_KEY`); no key in code | Secrets rule; `.env.example` holds placeholders only. |
| 6 | UNKNOWN, never NOT_MET, for: UCL TOEFL, UCL TARA, UCL non-A-level/IB qualifications, NUS missing/low GRE/GMAT, mismatched/missing budget | The verified sources state no threshold or no rejection rule; converting or rejecting would invent evidence. (Corrected 2026-11-24 audit: NUS IELTS components are NOT_APPLICABLE, not UNKNOWN — see #21; the UCL TOEFL reason was corrected — see #22; the NUS GRE/GMAT reason was corrected — see #23.) |
| 7 | NUS application deadline recorded as UNKNOWN (null) | Not stated on the admissions page; General Track dates deliberately not copied. |
| 8 | UCL BSc page recorded as `fetch_status: failed` (direct curl exit 18), facts from browser crawl | Honest provenance; no hash claimed for that page. |
| 9 | Fixture `fixture-p01` is synthetic, lives only in `data/fixtures/`, and the backend refuses fixtures in real data at startup | Test isolation without contaminating real data. |
| 10 | Overall status: any NOT_MET → NOT_MET; else any UNKNOWN → UNKNOWN; else KNOWN_MINIMUMS_MET | Deterministic summary rule shared by engine and tests. |
| 11 | CORS limited to `http://localhost:3000` | Frontend dev origin only. |
| 12 | Backend runs on port 8000, frontend on port 3000 | Convention agreed for the two-agent split. |
| 13 | Python 3.12 venv in the project (`.venv/`), pinned requirements in `backend/requirements.txt` | Reproducible local run; no paid resources. |
| 14 | Backend accepts BOTH API shapes: spec/test contract (single `program_id`, nested StudentProfile) and frontend contract (flat wizard profile + `program_ids`, multi-program response) | The two Day-1 agents built against different shapes; the adapter translates without touching rule logic. Both shapes are pinned by tests. |
| 15 | Adapter maps engine evidence ids (manifest fact ids) to frontend source ids | The frontend evidence drawer looks sources up by its own ids; unmapped ids would show an empty drawer. |
| 16 | Wizard budget assumed per-year for undergraduate, total for taught masters | Matches the wizard (currency defaults GBP for UG, SGD for masters); recorded as an assumption, not a verified fact. |
| 17 | Frontend source URLs fixed to the verified pages (NUS fees `/pg/mcs/scholarships/`, UCL `-2026` page, UCL English Level 1 page) and the A-level excerpt corrected to the page wording | The frontend draft used `/pg/mis/scholarships/` (typo, not the verified page) and a no-year UCL URL (403 via curl); the A-level excerpt invented an "A*AA" alternative the page does not state. |
| 18 | Day 1 scope grew: frontend integrated + GitHub push completed 2026-11-24 (HEAD ccf8aba, 14 commits, public repo) | Day 1 had been presented as done while the repo was still empty; the user selected PathPilot-AI in the GitHub App installation and the push was completed the same day. The audit fixes of 2026-11-24 still need a push. |
| 19 | UCL contextual offer (A*AB with A* in Maths; IB 38) → UNKNOWN, not NOT_MET | The official page lists the contextual offer as a real alternative route; marking it a failure invents a rejection. Without evidence of contextual eligibility it cannot be MET either. (Audit fix, tests added.) |
| 20 | NUS related-discipline route requires honours; a related bachelor's + 2y experience → UNKNOWN, not MET | The old engine branch contradicted the official four routes and produced a false MET — the spec treats a false MET as a release blocker. Business and computing bachelor's + 2y remain MET (listed routes). (Audit fix, tests added.) |
| 21 | NUS IELTS components → NOT_APPLICABLE, not UNKNOWN | No component minimum exists, so there is no component requirement to check; UNKNOWN made KNOWN_MINIMUMS_MET unreachable for every IELTS NUS applicant. (Audit fix, contract test updated.) |
| 22 | UCL TOEFL: a Level 1 mapping DOES exist on the cited Study Abroad English page (92 old iBT scale; 4.5 new scale for tests from 21 Jan 2026); keep UNKNOWN for now, never convert | The Day 1 claim that "no TOEFL threshold exists in the verified sources" was wrong — the cited page lists one. Converting from the wrong page/scale would be worse than UNKNOWN; modelling it needs a test date (Day 2, see #30). Wording corrected in the engine, manifest, and QUALITY_REPORT. |
| 23 | NUS GRE/GMAT "FAQ: not mandatory" citation removed; UNKNOWN stands on the verifiable reason | The fetched admissions page does not contain that FAQ statement. The page lists GRE/GMAT as evidence to submit but states no rejection rule for a missing/low score — that alone justifies UNKNOWN. Wording corrected in the engine, programs.json, manifest, QUALITY_REPORT, and adapter. |
| 24 | Frontend DATA_VERSION aligned to `v1` (was `pathpilot-day1-2026-11-24`) | One version string for one dataset; the backend ignores the frontend-sent version, so the mismatch was silent drift. (Audit fix.) |
| 25 | Offline evaluator aligned to the backend: GRE/GMAT below minimum → UNKNOWN (was NOT_MET); UCL TARA rule added; NUS components rule added; rule ids renamed to backend ids (ucl-fee, nus-fee, nus-academic, nus-language) | The fallback must not contradict live results, or the UI would show different verdicts depending on backend availability. Remaining offline gaps (no honours/experience fields in the flat profile) are Day 2 work. (Audit fix; verified by `npm run build`.) |
| 26 | POST /explain must recompute server-side (spec Ch12), not accept a client-supplied Evaluation | Accepting forged results lets a caller claim KNOWN_MINIMUMS_MET (demonstrated live in the audit). Not changed on Day 1 — the endpoint is unused by the frontend, and changing its shape is a Day 2 API decision. (BLOCKERS #8, TASKS D2-04.) |
| 27 | Default language stays en for now — user decision, not changed | Spec FR11 order is saved → browser → en, but the user has not answered whether the default should be en or zh-CN; changing it unilaterally would override an open question. Day 2: implement browser-language detection on first visit once the default is decided. |
| 28 | Spec Ch18 is a 5-day plan; the user's 3-day plan (Day 1 Nov 24, Day 2 Nov 25, Day 3 Nov 26, buffer to the Nov 28 deadline) is better | Leaves 2 buffer days before the 2026-11-28 15:00 PST deadline. Already the working plan; recorded here. |
| 29 | Spec Ch12 fixture example is test-harness only: fixture-p01 is not served by /match (404) and its evidence id is `fixture`, not `fixture-f01` | Ch14 isolation (production must refuse fixtures) outranks the illustrative example; the spec example should be read as a test-harness contract, not an API contract. |
| 30 | Spec Ch11 full StudentProfile model (id, schema_version, target_intake, education[], language_tests[] with dates) vs the Day 1 simplified profile | The spec's model is better for the full product; the Day 1 simplification was the right scope. But FR01 fields (intake year, test date, graduation status) must be added in Day 2 — without a test date, the UCL TOEFL Jan 2026 scale split and score-validity windows (BR02) cannot be implemented. |
| 31 | Money: Python float, not Decimal (spec Ch11 requires Decimal) | The spec is better — money must be exact. Day 1 float is fine for whole-number thresholds but must switch to Decimal before any currency conversion or per-unit maths in Day 2. |
| 32 | No rate limiting, security headers, or OpenAPI (spec NFR04 / Ch12) in Day 1 | The spec is better — add in Day 2 before the public preview link goes live; the preview will be internet-facing. (BLOCKERS #9, TASKS D2-06.) |
| 33 | No traceability.csv (spec Ch16) in Day 1; manifest + QUALITY_REPORT cover the same ground | Generate a traceability.csv in Day 2 derived from the manifest rather than hand-maintaining a third copy. (BLOCKERS #9.) |
| 34 | /programs has no filtering/pagination (spec Ch12: country/subject/intake/cursor/limit, next_cursor); /profile/validate returns only {valid, application_track} (spec: normalized_profile/warnings/field_errors) | The spec is better — needed once Day 2 grows to 8+ courses; acceptable with 2 courses on Day 1.
